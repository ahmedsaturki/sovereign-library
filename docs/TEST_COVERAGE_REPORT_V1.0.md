## Test gaps identified by this wave

These are gaps that existed before the hardening wave; documenting
them here so the next wave can address them.

1. The Android conformance runner reads the vector file from the
   classpath (`ClassLoader.getResourceAsStream`). If the vector
   file is missing or unreadable, it throws
   `IllegalStateException` with a non-machine-readable error code.
   The wave adds a unit test gap; the next hardening wave should
   add a "missing vector file" test.
2. The Python port for `validation` lacks an explicit
   `vectors.validation.json` and is therefore exercised only by
   its native pytest. Conformance-pinning it should be a
   separate, smaller wave.
3. The hardened `security-pipeline.yml` adds no new code-coverage
   tests; it is itself covered by the `lint-workflows` step
   (actionlint and yamllint will fail the wave if the workflow
   has a syntactic bug).

## How to reproduce

1. Local lint pass:
   ```bash
   pip install yamllint
   yamllint -c .yamllint.yml .
   ```
2. CI full pass (push to `feat/continuity-hardening` and watch
   the GitHub Actions UI; all six workflows should turn green).
3. Local Kotlin compile pass (requires JDK 17 + Android SDK):
   ```bash
   cd ecosystems/android
   ./gradlew :safe-path-resolver:assembleRelease :conformance:assembleRelease
   ```
4. Local Kotlin test pass:
   ```bash
   cd ecosystems/android
   ./gradlew test
   ```
5. Conformance runner (Android JVM-hosted):
   ```bash
   cd ecosystems/android
   ./gradlew :conformance:test
   ```
