# ADR-0009 — Why STRIDE + PASTA threat modelling is mandatory

**Status:** Accepted
**Date:** 2026-09-07
**Deciders:** @sovereign/fellow-engineer
**Consulted:** @sovereign/security-team
**Informed:** @sovereign/engineering-all

## Context

Several Phase-2 cubes ship security-sensitive surfaces
(safe-path-resolver, policy-capability-security,
release-verification-harness). Without a structured threat model,
the security review is ad-hoc and depends on individual reviewer
experience.

## Decision

For every cube in `security/threat-modeling/registry.json`, the
cube must have both a STRIDE report and a PASTA report on file
under `security/threat-modeling/reports/`. Reports are generated by
`scripts/threat-model.mjs` from a YAML DSL, with human review.

## Alternatives Considered

- **STRIDE-only** — rejected; STRIDE alone misses attacker-perspective
  reasoning. PASTA adds that.
- **PASTA-only** — rejected; PASTA is heavier; STRIDE gives the
  quick read.

## Consequences

- Positive: consistent threat model across cubes.
- Negative: documentation overhead. Mitigated by automation.
